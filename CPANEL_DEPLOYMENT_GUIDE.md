# Complete cPanel Node.js Deployment Guide

This guide walks you through deploying your **Sellvro** application on **cPanel** using the **Setup Node.js App** (CloudLinux / Phusion Passenger) environment.

---

## 1. How the Architecture Works on cPanel

Sellvro is configured as a **single unified application**:
- **Backend**: Express.js server providing REST API endpoints (`/api/*`), MongoDB connection, authentication, and email services.
- **Frontend**: Vite React application compiled into the static `dist/` directory.
- **Unified Routing**: When deployed on cPanel, Express serves the `dist/` static files and automatically handles client-side React routing (so page refreshes on `/admin/dashboard`, `/login`, `/supplier/products` work without 404 errors).
- **Startup Entry**: The root [app.js](file:///d:/HayViral%20internship/Sellvro%20project%202/app.js) file is recognized natively by cPanel's Node.js Selector.

## 2. Preparing Files for Upload

### Required Files & Folders
Ensure you upload the following files to your cPanel application root directory:
```text
├── app.js                   (Startup file for cPanel Phusion Passenger)
├── package.json             (Dependencies and scripts)
├── package-lock.json        (Lockfile)
├── .htaccess                (Apache rules, security protection for .env, HTTPS)
├── .env                     (Production environment variables)
├── server/                  (All backend routes, models, and controllers)
│   ├── config/
│   ├── controllers/
│   ├── middleware/
│   ├── models/
│   ├── routes/
│   ├── utils/
│   └── server.js
└── dist/                    (Pre-built frontend generated by npm run build)
    ├── index.html
    └── assets/
```

> [!IMPORTANT]
> **DO NOT upload `node_modules`** or `.git`. Dependencies should be installed directly on the cPanel server to match the Linux architecture.

### Creating the ZIP File for Easy Upload
You can create a zip file on your local machine containing the above folders and upload it via **cPanel File Manager**, then click **Extract**.

## 3. Step-by-Step cPanel Configuration

### Step 1: Open "Setup Node.js App"
1. Log in to your **cPanel dashboard**.
2. Scroll down to the **Software** section and click **Setup Node.js App**.

### Step 2: Create the Node.js Application
Click the **"Create Application"** button and fill in the fields:
- **Node.js version**: Select **20.x** (or **18.x** / **22.x** depending on your host).
- **Application mode**: Select **Production**.
- **Application root**: The directory where your files are located:
  - If deploying to your primary domain, typically `public_html` or `/home/yourusername/sellvro`.
  - If deploying to a subdomain, typically `sellvro` or `subdomains/sellvro`.
- **Application URL**: Select your domain from the dropdown (e.g., `yourdomain.com`).
- **Application startup file**: Enter `app.js`.
- **Passenger log file** (optional): `stderr.log`.

Click **CREATE** (or **SAVE**).

---

### Step 3: Install Node.js Dependencies
Once the application is created in cPanel:
1. In the Node.js app dashboard, look for the button labeled **"Run NPM Install"** (or **"NPM Install"**).
2. Click **Run NPM Install** and wait for cPanel to download and install all runtime dependencies.
3. *Alternative via SSH/Terminal:*
   cPanel provides an activation command at the top of the page (e.g., `source /home/username/nodevenv/public_html/20/bin/activate && cd /home/username/public_html`).
   Run that in the cPanel Terminal, then execute:
   ```bash
   npm install --omit=dev
   ```

---

### Step 4: Configure Environment Variables
You can create or edit the `.env` file directly in cPanel File Manager (or use the **Environment variables** table in the Node.js App interface).

Sample production `.env`:
```ini
# Production Environment
NODE_ENV=production

# MongoDB Atlas Connection String
# (Make sure to whitelist your cPanel server IP in Atlas!)
MONGODB_URI=mongodb+srv://AJAY_Chauhan:Sellvro123@cluster0.se51g8e.mongodb.net/sellvro?retryWrites=true&w=majority

# JWT Authentication Secret
JWT_SECRET=your_strong_random_jwt_secret_key_here
JWT_EXPIRES_IN=7d

# Allowed Client Domain(s)
CLIENT_URL=https://yourdomain.com

# (Optional) SMTP Mail Configuration for OTP & Password Recovery
# You can use your cPanel Webmail account credentials:
SMTP_HOST=mail.yourdomain.com
SMTP_PORT=465
SMTP_USER=no-reply@yourdomain.com
SMTP_PASS=your_email_password
SMTP_FROM="Sellvro" <no-reply@yourdomain.com>
```

> [!NOTE]
> If you do not configure SMTP credentials immediately, the server will fallback to logging the 6-digit OTP verification codes into the server output log (`stderr.log`), allowing you to test account recovery without live email credentials.

---

### Step 5: Configure MongoDB Atlas Network Access
cPanel servers have a static external IP address.
1. Log into your [MongoDB Atlas Console](https://cloud.mongodb.com/).
2. Go to **Security** → **Network Access**.
3. Click **Add IP Address**:
   - Add your **cPanel Shared/Dedicated Server IP**, OR
   - To allow access from any server, add `0.0.0.0/0` (Allow Access from Anywhere).

---

### Step 6: Start & Restart the Application
1. In cPanel **Setup Node.js App**, click **Restart Application**.
2. Visit `https://yourdomain.com/` in your browser.
3. Verify:
   - Homepage and login load seamlessly.
   - Test login and navigation across `/admin/*`, `/supplier/*`, and `/user/*`.
   - Test topbar search and notification bell.

## 4. Troubleshooting Common cPanel Issues

### Issue 1: "503 Service Unavailable" or "Application failed to start"
- **Cause**: Node.js encountered a startup crash (usually invalid MongoDB credentials or missing dependency).
- **Solution**: Open cPanel File Manager, look for `stderr.log` in your application root folder. The exact error trace will be printed there.

### Issue 2: "MongoDB Connection Timeout / ServerSelectionError"
- **Cause**: MongoDB Atlas is blocking incoming connections from your cPanel server IP.
- **Solution**: In MongoDB Atlas → Network Access, add `0.0.0.0/0` or add your cPanel IP address.

### Issue 3: Page refresh gives 404 on React routes
- **Cause**: Missing SPA fallback rule.
- **Solution**: Handled automatically! Our updated [server.js](file:///d:/HayViral%20internship/Sellvro%20project%202/server/server.js) serves `dist/index.html` for all client-side routes, and [.htaccess](file:///d:/HayViral%20internship/Sellvro%20project%202/.htaccess) directs all requests through Passenger.

### Issue 4: Permissions
- Ensure directories have permission `755` and files have permission `644`.
